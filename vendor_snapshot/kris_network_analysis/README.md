# Epstein Email Network and Dyad Classification

Course project for **Using Geography and Text in Data Science**.

Reproducible pipeline that parses the public EPS 20K email corpus, builds an
interaction graph, and classifies actor *dyads* (unordered pairs of people) as
`business`, `friend`, or `mixed` from text and email-domain features. The
pipeline is available both as a runnable `python run_pipeline.py` CLI
(`src/stage0N_*.py`) and as matching notebooks (`codes/0N_*.ipynb`) — the two
paths share the same logic and write to the same `output/` paths.

## Research question

Do business and friend ties form structurally distinct sub-networks in the
Epstein email corpus, and to what extent is any observed structure an artifact
of Epstein's centrality rather than a property of the ties themselves?

The unit of analysis is the **dyad**, not the person — so the result doesn't
collapse into a centrality-of-Epstein story.

## Quick start — reproducible pipeline

The whole analysis runs from one command. The first run downloads the corpus
(~250 MB) from HuggingFace, the MiniLM-L6-v2 model (~80 MB) on first
`SentenceTransformer` call, and three NLTK resources (~10 MB). All subsequent
runs are offline.

```bash
# 1. create a virtualenv, install dependencies, pre-fetch NLTK resources
./setup.sh

# 2. activate the environment
source .venv/bin/activate

# 3. run the full pipeline (≈ 1–2 min on a recent laptop, dominated by stage 3)
python run_pipeline.py
```

`setup.sh` is idempotent — re-running it reuses an existing `.venv/`. To use a
different interpreter, pass `--python`, e.g. `./setup.sh --python python3.11`.

The pipeline writes every artifact deterministically to `output/` (CSVs +
parquet) and `figures/` (PNGs). With the seeds baked into the code
(`np.random.default_rng(7)`, `random_state=42`, `LdaModel(random_state=0)`,
spring-layout `seed=7`) **all CSVs are byte-identical across runs** on the
same dependency versions.

### Partial reruns

```bash
python run_pipeline.py --only 3              # just stage 3
python run_pipeline.py --from 2              # skip the download
python run_pipeline.py --from 3 --to 4       # stages 3 and 4
```

Each stage reads only its predecessor's outputs, so a partial run is safe as
long as the upstream artifacts already exist on disk.

### Running stages directly

The stages are importable modules; each has a `main()` and is also a
runnable script:

```bash
python -m src.stage01_email_extraction
python -m src.stage02_name_extraction
python -m src.stage03_dyad_classification
python -m src.stage04_additional_visualizations
```

### Interactive / notebook workflow

The notebooks in `codes/` mirror the .py modules line-for-line and remain the
recommended EDA surface — useful for inspecting intermediate frames,
re-tuning lexicons, or reading the analysis narrative inline. After `./setup.sh`:

```bash
jupyter lab
```

Run the notebooks in order: 01 → 02 → 03 → 04. They read and write the same
`output/` files as the .py pipeline, so the two paths are interchangeable.

## Pipeline summary

Each stage exists as both a .py module (`src/stage0N_*.py`) and a matching
notebook (`codes/0N_*.ipynb`); the two paths share the same logic and write
to the same `output/` paths.

- **Stage 01** — downloads the corpus, splits each thread file into individual
  messages (handles Outlook and Gmail quote styles), deduplicates messages
  that get re-quoted across threads via a `(sender, timestamp, body[:200])`
  hash, writes `output/intermediates/01_email_threads.parquet`.

- **Stage 02** — reads the parquet and does two things:
  1. canonicalises sender / recipient / cc names (OCR cleanup) and
     pre-computes per-message domain info (sender domain kind + `any_corp` /
     `any_known` flags). One row per message →
     `output/intermediates/02_mail_messages.parquet`. Includes a safety-net
     dedup on canonical sender / timestamp / body[:200].
  2. aggregates those messages into a sender→recipient interaction graph →
     `output/interactions/02_mail_names.csv`,
     `02_mail_interactions_edges.csv`, `02_mail_interactions_nodes.csv`.

- **Stage 03** — loads `intermediates/02_mail_messages.parquet`, explodes
  each message into all unordered participant pairs, pools bodies per dyad,
  computes text + domain features, and labels each dyad in two layers:

  1. **Rule-based** — a hand-built lexicon (V1) seeds a TF-IDF-derived V2
     lexicon, then

     ```
     net_score = (biz_z − friend_z) + 0.5 × corp_either_z
     ```

     is bucketed at ±0.5 σ → `business` / `friend` / `mixed`. The corp term
     uses a NaN-safe z-score: dyads with no readable email domain on any role
     get `corp_either_z = 0` rather than a fabricated fillna value. The
     `mixed` band is by construction the rule's low-confidence zone — it is
     handed entirely to the next layer.

  2. **Embedding fallback over the entire mixed band** — every rule-mixed
     dyad is re-scored using `sentence-transformers/all-MiniLM-L6-v2` +
     binary logistic regression (trained on the rule's confident business /
     friend calls). Predictions clearing the 0.55 confidence floor get the
     embedding model's class; the rest stay labelled `mixed` (rule uncertain
     *and* embedding model uncertain). The three final classes are
     `business`, `friend`, `mixed`.

  Production settings: `MIN_MESSAGES = 2`, `T = 0.5`, fallback confidence
  floor = 0.55. Final class counts: **127 business, 90 friend, 59 mixed**
  (n = 276 dyads).

- **Stage 04** — supplementary figures only. Reads the CSVs in
  `output/network/`, `output/labels/`, `output/robustness/` and
  `output/intermediates/03_dyads.csv`; produces four PNGs in `figures/` for
  the written analysis. The permutation null distributions are re-sampled
  here (same seed `np.random.default_rng(7)`, `N_PERM = 500` as stage 03)
  because stage 03 persists only observed / mean / p-value summaries.

Stage 03 does **not** re-read `intermediates/01_email_threads.parquet`; it
consumes `intermediates/02_mail_messages.parquet` directly. Stage 04 only
reads CSVs that stage 03 saves in `output/`.

## Robustness checks (stage 03)

- T-sensitivity sweep at T ∈ {0.3, 0.5, 0.7, 1.0} → `output/robustness/03_threshold_sensitivity.csv`
- MIN_MESSAGES sweep at {2, 3, 4} with per-dyad label stability across
  thresholds (dyads dropped at a higher cutoff are flagged `absent`) →
  `output/robustness/03_min_messages_*.csv`
- Bootstrap CIs (500 iter, 5/50/95 percentiles) per class → `output/network/..._bootstrap*.csv`
- Permutation / label-shuffle test (500 iter, two-tailed) — shuffles `tie_type`
  across dyads and rebuilds the sub-graphs. Tests whether the labels carry
  structural information given the underlying graph. → `output/network/..._permutation*.csv`
- Degree-preserving random-graph null (500 iter, two-tailed) via
  `nx.double_edge_swap` → `output/network/..._random_baseline*.csv`. Tests
  whether observed clustering / modularity / largest_cc_frac exceed what each
  sub-graph's degree sequence alone produces. Density is preserved by
  construction (reported but degenerate).
- Every network statistic and figure is reported in two views: **with
  Epstein** and **without Epstein**.

## Key result

Tested against two complementary nulls — **label-shuffle permutation**
(does the label assignment carry structural info given the underlying
graph?) and **degree-preserving random graphs** (does the sub-graph's
structure exceed what its own degree sequence produces?):

- **Business is structurally real.** Both nulls reject random structure on
  clustering. Label-shuffle p ≈ 0 for clustering with **and** without Epstein.
  Degree-preserving null without Epstein: clustering z ≈ +22.2 and modularity
  z ≈ +8.5 (both p ≈ 0). Sub-network shrinks only modestly (96 → 67 nodes)
  when Epstein is removed — business is **not** Epstein-anchored.

- **Friend collapses without Epstein.** Both nulls agree. Label-shuffle gives
  density / clustering / modularity p = 0.28 / 0.14 / 0.83 — none significant.
  Degree-preserving null without Epstein: modularity z ≈ +1.2 (p = 0.16) —
  indistinguishable from a random graph with the same degree sequence. The
  sub-network falls to 24 nodes / 16 edges, at the floor of stable network
  statistics.

- **Mixed is a substantive residual** (~21 % of dyads): rule uncertain *and*
  embedding LR's confidence below 0.55. Density and clustering are highly
  significant under both nulls (label-shuffle p ≈ 0 with and without Epstein;
  degree-preserving clustering z ≈ +6.3 without Epstein). It's a borderline
  communications class — not a no-signal sink.

The two nulls answer different questions, so they don't always land at the
same p-value (most clearly: business modularity is null under label-shuffle
but well above the degree-preserving null without Epstein — the latter is the
tighter test for within-class community structure).

### Anti-modularity with Epstein (degree-preserving null only)

In the with-Epstein view, observed modularity is *below* the
degree-preserving null mean for all three classes (z = −24.9, −71.0, −19.0
for business / friend / mixed). A degree-matched random graph with one
super-hub would still partition into communities; the observed graph
partitions *less*. Read: Epstein acts as a bridge across what would
otherwise be separable groups — an integrator, not just a hub. Once he is
removed, business modularity flips to z ≈ +8.5 (community structure
beneath the integration effect).

Full numbers: `output/network/03_subnetwork_stats_permutation*.csv` and
`..._random_baseline*.csv`. The per-class side-by-side network figures
(`figures/03_dyad_class_*_with_without_epstein.png`) and the slope chart
(`figures/04_epstein_removal_slopes.png`) are the visual counterparts of
this section.

## Dyad definition

A dyad `(a, b)` exists when both names appear together in at least
`MIN_MESSAGES` messages' participant sets (sender ∪ To ∪ Cc). Neither needs
to have actively written to the other — being co-recipients on the same
email counts. This is "co-participation," not "active conversational pair."
The validation sample includes a banner reminding human reviewers of this so
they don't expect every dyad to be a back-and-forth exchange.

## Validation

`output/content/03_dyad_validation_examples.md` is a hand-readable sample of 5
dyads per class, regenerated by the validation section of stage 03.
Quoted-reply chains are stripped at unambiguous boundaries; near-duplicate
forwards are collapsed via fuzzy similarity. Dyads are sampled with
`random_state=42` from a deterministic readability window
(`2 ≤ n_messages ≤ 6`, `80 ≤ n_tokens ≤ 1500`) — meant for narrative
inspection, not for statistical precision/recall estimates. The current label
CSVs in `output/labels/` are model predictions, not human-validated truth.

## Dependencies

`./setup.sh` (recommended) creates a `.venv/`, installs everything pinned in
`requirements.txt`, and pre-fetches the NLTK resources. To install manually:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m nltk.downloader stopwords wordnet omw-1.4
```

Uses `pandas`, `numpy`, `pyarrow`, `requests`, `matplotlib`, `networkx`,
`scikit-learn`, `nltk`, `gensim`, `sentence-transformers`. The MiniLM-L6-v2
sentence-transformer (~80 MB) is downloaded by `sentence-transformers` on
first call.

Tested on Python 3.13 with the lower-bound versions listed in
`requirements.txt`. Earlier Python (3.10+) should work as long as the
dependency lower bounds are met.

## Reproducibility notes

All RNG-driven steps are seeded:

- `np.random.default_rng(7)` — bootstrap, permutation null, degree-preserving
  null in stage 03; re-used in stage 04's permutation re-sample.
- `LdaModel(..., random_state=0)` — LDA topic model.
- `random_state=42` — validation-sample stratified draw.
- `nx.spring_layout(..., seed=7)` — network figure layouts.

With pinned dependency versions the **CSV outputs are byte-identical across
runs**. The PNG figures match up to small font-rendering differences from
matplotlib's Agg backend (≤ ~1 % byte difference); pixel-level equality
across machines isn't guaranteed.
